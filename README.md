This repository documents the comparative genomics workflow for human skin-associated  *Staphylococcus hominis* , including genome collection and screening, quality control, dereplication, species verification, population structure analysis, and functional annotation.

**Analysis workflow**

1. **Metadata retrieval and genome screening.** RefSeq assembly accessions for all *S.* *hominis* genomes available at the time of data collection were retrieved from NCBI Datasets and recorded ingenome_info_list.txt. The script download_ncbi_genome_metadata.py used this list to retrieve the corresponding metadata and save them to genome_ncbi_info.xlsx. Assemblies were retained if theHost field indicated a human host and the Isolation source field documented a skin or skin-associated source. For the retained records, the RefSeq assembly accession and assembly name were taken from the Assembly accession and Accession fields, respectively, and saved as two tab-delimited columns in genome_accession_list.txt.
2. **Assembly download.** download_ncbi_genomes.sh used genome_accession_list.txt to download the compressed whole-assembly FASTA files. The files were decompressed before quality assessment.
3. **Quality control and dereplication.** checkm.sh used the assembly FASTA files to estimate completeness and contamination and report both values in a quality summary. Assemblies with ≥95% completeness and ≤5% contamination were retained and dereplicated with dRep.sh at 99.9% average nucleotide identity (ANI). The representative assembly FASTA files were saved in dereplicated_genomes/.
4. **Genome annotation.** prokka.sh annotated the representative assemblies and generated GFF annotation files (.gff) and predicted protein FASTA files (.faa). The GFF files were used for pan-genome analysis, and the protein sequences were used for gene screening.
5. **ANI analysis and species verification.** fastANI.sh took a list of representative assembly FASTA paths and generated a pairwise ANI table and matrix. ANI values for comparisons with the *S. hominis* type strain NCTC 11320ᵀ (GCF_002901845.1) were extracted from the pairwise output. Digital DNA–DNA hybridization (dDDH) values for comparisons with the type-strain assembly were estimated using GGDC formula 2.
6. **Pan-genome and phylogenetic analyses.** panaroo.sh used the Prokka GFF files to generate a gene presence–absence table (gene_presence_absence.csv) and core-gene alignments. The filtered core-gene alignment (core_gene_alignment_filtered.aln) was used by iqtree.sh to infer a maximum-likelihood tree (S_hominis_core.treefile).
7. **Population structure and recombination.** poppunk.sh used a list of sample names and their corresponding assembly FASTA paths to generate a lineage assignment table. gubbins.sh analyzed each lineage alignment separately and generated files listing putative recombination regions, along with filtered alignments for downstream analyses.
8. **Functional annotation and gene screening.** eggNOG-mapper used the Panaroo-generated pan_genome_reference.fa file to produce a functional annotation table. vf.sh and rgi.sh used the Prokka protein FASTA files to generate VFDB similarity search results (_vfdb.blast) and CARD antimicrobial resistance predictions (.txt and *.json), respectively. SCCmecFinder used the representative assembly FASTA files to assign SCCmec types.

**Software versions and analysis parameters are documented in the corresponding scripts and in the manuscript’s methods section.**
